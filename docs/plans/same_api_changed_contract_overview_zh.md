# “Same API, Changed Contract”课题总览与阶段计划

日期：2026-07-20
状态：研究设计已锁定；尚未授权新仓库创建、数据获取/生成、模型选择、API、训练或实验

## 一句话研究主张

本研究拟检验：当工具名称和参数 schema 保持不变、当前契约明确可见、任务与状态等其他条件
保持一致时，大语言模型工具智能体能否因一个可执行契约原子的变化而正确改变实际行动，并在
语义等价改写下保持行动稳定；研究将以可执行有限状态环境、独立机械 oracle、配对指标和真实
版本迁移案例建立证据，但结论只限于可观察的契约服从，不外推为模型内部因果理解或生产系统
安全保证。

## 1. 课题名称与类型

- 中文暂定题目：**稳定 API 表面下工具契约变化的大模型智能体配对可执行评测**。
- 英文暂定题目：**Same API, Changed Contract: Paired Executable Evaluation of LLM
  Tool-Agent Compliance**。
- 小论文类型：benchmark / evaluation protocol / empirical study，而不是新损失函数论文。
- 硕士论文类型：在小论文证明确有稳定缺口后，再扩展为契约组合、持续更新或结构化适应方法。
- 学科边界：研究对象是大模型工具智能体，不因通信工程专业名称强行加入通信场景。

## 2. 核心术语

| 规范术语 | 含义 |
|---|---|
| 工具契约（tool contract） | 决定工具调用何时允许、调用后产生何种状态变化以及失败后如何处理的可执行语义 |
| 契约原子（contract atom） | 一条可以独立改变并由状态机执行检查的最小契约规则 |
| 翻转对（flip pair） | 只改变一个契约原子，并使同一 witness action 的许可标签翻转的一对实例 |
| 等价对（equivalent pair） | 只改变表述或无关字段，但合法行为集合保持不变的一对实例 |
| Witness action | 在两侧保持完全相同、用于诊断许可状态是否翻转的规范化动作 |
| Paired Compliant Completion（PCC） | 一对执行任务的两侧都无契约违规且完成目标才记为成功的主要指标 |
| `root_id` | 一个语义根及其全部改写、派生和重复推理的共同统计与切分标识 |
| `source_change_event_id` | 一个真实官方版本变更事件及其全部派生案例的最高依赖标识 |

## 3. 研究背景与意义

工具型大模型正在从“生成一段文本”转向“依据文档和状态调用外部工具”。在实际软件生态中，
接口名称和参数结构可能保持稳定，但幂等范围、重复副作用、原子提交、部分提交或补偿前提等
执行语义会发生变化。此时，调用在格式上仍然正确，却可能在当前契约下产生重复操作、遗漏
状态核验、错误重试或错误补偿。

现有研究已经覆盖规则更新、工具演化、指令服从、反事实配对训练和契约评测的多个部分，因此
本课题不能把“规则会变化”“配对数据”或“微调后准确率提高”单独称为创新。仍值得检验的窄
问题是：在工具表面稳定的严格配对控制下，模型是否真正根据当前可见契约改变可执行行动，
而不是依赖工具名、关键词位置、旧契约先验或固定保守策略。

这一问题有三层意义：

1. **测量意义**：普通逐样本准确率无法区分“契约变化时应该改变”与“语义等价时不应改变”；
   配对指标可以同时测量敏感性和稳定性。
2. **工程意义**：它对应接口未破坏但执行语义已经改变时的隐蔽维护风险，可帮助模型开发者判断
   应优先使用文档重读、契约检索、显式解析器、参数适应还是运行时约束。
3. **研究意义**：它把模糊的“模型是否理解规则”转化为可执行、可反驳、具有停止条件的行为
   问题，并明确区分 benchmark 价值与训练方法价值。

## 4. 解决的实际问题

本研究针对的是**接口兼容但行为契约漂移**。例如，以下只是待编码的说明性情形，不是已有
实验结果：

- 某次有副作用的调用超时后，旧契约允许用同一请求标识安全重试，新契约却改变了幂等范围或
  有效期；智能体若沿用旧策略，可能产生重复副作用。
- 批量操作原先保证全有或全无，更新后允许部分提交；智能体若仍按原子提交假设整体重试或
  补偿，可能扩大错误。
- 两份契约仅改变措辞或字段顺序，实际语义不变；智能体若无故改变行动，说明其行为受表面
  文本扰动影响。

课题最终要回答的不是“微调能否提高一个分数”，而是：现有模型在这类变化下是否存在稳定且
可复现的行为缺口；什么类型的方案能够修复；修复能否迁移到未见工具族、未见契约组合和独立
真实版本事件，同时不损害普通工具调用能力。

## 5. 科学问题与可证伪假设

### RQ1：契约敏感性

固定任务、工具 identity/schema、初始状态和除契约外的历史，只改变一个可见契约原子时，
模型能否在诊断判断和闭环执行中作出应有变化？

- H1：至少一个预注册强模型在严格 OOD 上的 PCC 未达到 95%，且主要错误可归因于未按当前
  契约作出应有行动变化，而不是 DSL、renderer 或输出解析失败。
- No-Go：若强模型和确定性 parser/planner 在严格 OOD 上都近饱和，则缺少训练研究张力。

### RQ2：语义不变性

契约语义不变、仅表述或无关结构改变时，模型能否保持合法性判断和行动稳定？

- H2：模型的契约敏感性与表面文本敏感性可以被配对控制区分。
- No-Go：若所谓差异主要由长度、位置、关键词或工具名称预测，则修复数据或停题。

### RQ3：可解释的缺口来源

文档重读、相关条款检索、结构化输出、确定性自然语言解析器与精确规划器、普通 SFT/DPO 和
已有配对方法分别能够解释或修复多少缺口？

- H3：如果参数训练仍有价值，其增益应超过等数据、等 token、等计算预算的强基线，并在
  root-closed OOD 与能力保持测试上成立。
- No-Go：若简单解析器即可解决，取消“需要微调”的论点，不人为增加语言噪声压低基线。

### RQ4：外部迁移

合成环境中观察到的现象能否迁移到独立的官方版本契约变化事件？

- H4：至少部分错误模式可在按 `source_change_event_id` 隔离的真实文档语义变化中复现。
- No-Go：若无法获得不少于 30 个独立变化事件、5 个工具族和两个核心契约族，则不能主张现实
  版本迁移，必须重新评估选题价值。

## 6. 预期创新点及其边界

预期贡献不是任何单一组件，而是以下合取是否形成新的可识别测量单位；在数据构造前仍须用
全文维度矩阵继续反证：

1. 稳定工具 identity/schema 下的单契约原子可执行干预。
2. 同一 witness action 的机械许可翻转与语义等价控制。
3. 排除共同保守策略的 policy-separation 证明，以及闭环 PCC 指标。
4. 以 `root_id` 和 `source_change_event_id` 封闭的数据谱系、OOD 切分和统计分析。
5. 合成形式环境与独立真实版本文档迁移承担不同证据角色。

不作为创新的内容包括：普通 SFT/LoRA、DPO、对比学习、反事实配对本身、有限状态机本身、
工具故障恢复本身，以及“模型精度随证据增加而提高”的一般现象。没有实验结果前也不声称
首次、显著提升、通用安全或生产可靠性。

## 7. 数据从哪里来

数据分为两层，不能互相替代：

1. **合成主集**：由研究者定义的有限状态工具 DSL 生成语义根，再从已验证 AST 渲染为自然
   语言。它用于精确控制变量、生成无歧义标签和构造 OOD；generator 不得产生最终标签。
2. **现实外部集**：以后经单独授权，从有版本号和日期的官方 API 文档、SDK release notes、
   changelog、公开规范仓库及官方 conformance/contract tests 中重新采集。每个案例必须保留
   旧版本证据、新版本证据和官方变更说明，且不得从当前旧课题仓库的数据或结果中选择案例。

自建 mock 只能证明内部语义一致，不能证明真实 API 行为。只有供应方版本化测试、官方规范
测试或独立可执行 artifact 才能把某个现实案例升级为行为证据。

## 8. 自生成数据如何保证可靠

- R1 构造有效性：类型、可达性、终止性、状态不变量、目标可达、单原子 AST diff 和策略分离
  全部通过。
- R2 标签独立性：人工推导 gold suite、显式枚举和独立符号求解三方 100% 一致；声明内
  mutants 必须全部被测试杀死。
- R3 文本忠实性：从 AST 单向渲染；两名独立审阅者核对现实 roots 全部以及合成 roots 的分层
  样本，合成审计 `Cohen's kappa >= 0.80`。
- R4 泄漏与捷径：所有派生保留在同一 `root_id` split；关键词、位置、长度、工具名和
  bag-of-words 基线不得在严格 OOD 上近饱和。
- R5 外部有效性：现实案例按独立版本变更事件聚类并满足来源、数量、工具族和契约族 Gate。

其中 100% oracle 一致、事件数、kappa 和 95% shortcut 阈值是本项目预注册的工程与停止阈值，
不是所有研究都必须采用的普适常数。

## 9. 实验与证据链

研究按 Gate 推进，前一阶段失败时不得继续堆算力：

1. **Phase 0：规范脚手架**——冻结 DSL、schema、两个独立 oracle 接口、策略分离证书和
   fail-closed 授权检查；仅使用永久标注为非研究数据的极小手工自检例。
2. **Phase 1：来源可行性**——先证明现实版本事件的数量和类型可达标，再决定是否建数据集。
3. **Phase 2：无模型 feasibility**——验证五层 Gate、lineage、标签平衡、浅层基线和精确
   parser/planner，不调用大模型。
4. **Phase 3：最小模型 pilot**——冻结至少两个模型家族和两个能力档，测试 prompt-only、
   契约重读、条款检索和结构化输出；模型名称在执行前根据许可与可复现性另行确定。
5. **Phase 4：完整 benchmark**——按 root cluster 报告 PCC、Flip Pair Accuracy、等价对
   invariance、OOD 与失败类型；每个预注册模型的 PCC 区间半宽目标不超过 5 个百分点。
6. **Phase 5：训练基线**——只有存在稳定 headroom 时才运行 LoRA/SFT、DPO 和已有配对方法；
   训练至少三个随机种子，并检查标准工具调用能力保持。
7. **Phase 6：论文冻结**——完成可重建脚本、schema、manifest、hash、审计报告、统计与边界
   声明，再按投稿当年的 EI/Compendex 和学校认定选择目标，不提前保证录用。

现有 4 张 A6000 和 3 张 RTX 3090 足以承担多模型推理、7B/14B 量级的参数高效适应和多随机
种子基线，但不构成创新理由，也没有必要进行基础模型预训练。

## 10. 小论文与硕士论文的关系

### EI 小论文的最短闭环

小论文先完成 benchmark/protocol/empirical study：证明问题可测、标签可信、配对指标确实揭示
逐样本指标遗漏的行为、强基线仍留有边界，并检查现实文档迁移。即使训练方法没有新意，只要
测量对象明确、证据可靠、结果有非平凡发现，仍可形成独立论文；是否达到具体 EI 期刊要求需
投稿前重新核验。

### 硕士论文的条件扩展

只有同时满足以下条件才进入方法扩展：模型缺口可重复；parser/planner 未近饱和；普通
SFT/DPO 与已有配对基线仍留下 OOD 缺口；新方案能在 held-out 现实事件上取得预注册的实际
改进且不损害基础能力。可选扩展限于多契约原子组合、版本序列、持续适应、结构化契约表示，
以及参数适应与运行时 enforcement 的比较。若条件不成立，小论文收尾，硕士方向重新过
创新 Gate，不强行沿错误方向扩展。

## 11. 工作目录与 GitHub 仓库决策

### 结论

**正式实施前建议新建当前仓库之外的同级工作目录，并建立独立私有 GitHub 仓库。** 仅在
`research95/future_studies/` 下继续开发可以满足现有流程的逻辑隔离，但不是最纯净、最易解释
的长期方案。

### 原因

- 当前仓库保存多条已终止研究线、旧数据、旧结果、旧 prompt、旧执行脚本和旧论文草稿；它们
  虽被 manifest 与 loader 禁止用于新研究，文件仍在物理上可读。
- 新仓库能使 Git 历史从课题确定时开始，降低脚本误读、全文搜索误引用、错误暂存、复现包
  混入历史 artifact 和导师/审稿人误解研究谱系的风险。
- 小论文与硕士论文可共享同一干净仓库，通过阶段目录或版本标签扩展，无需以后再次搬家。

### 迁移边界

新仓库只能迁移人工白名单中的规范性材料：本总览、锁定计划的必要部分、空 schema、术语表、
授权模板和重新实现的最小审计规则。禁止复制旧研究数据、旧结果、旧 prompt、旧模型输出、
旧实验脚本、历史论文结论和任何由旧结果驱动的选择顺序。当前仓库保留只读归档作用。

本文件只给出决策，不授权创建目录、创建 GitHub 仓库或迁移文件。执行时还需单独确认目录名、
仓库名、是否私有、迁移白名单和首次提交内容。在确认并建立新仓库自己的 fail-closed 授权
边界前，当前 `PLAN.md` 与空 manifest 仍是执行权威；不能把“换一个目录”当成绕过数据、模型
或实验授权的方式。

## 12. 最近的下一步

1. 作者确认“新建同级目录＋独立私有仓库”的物理分仓方案。
2. 在不复制历史研究材料的前提下，建立空仓库、README、研究边界、授权清单和阶段 Gate。
3. 单独授权 Phase 0 后，只实现无数据、无模型、无 API 的规范与验证脚手架。
4. Phase 0 通过后，再单独决定是否授权官方来源可行性调查和研究输入 manifest。

## 13. 主要缺口与停止条件

- 尚无任何模型结果，因此 H1--H4 都是待检验假设，不是结论。
- 现实版本变化事件能否达到最低数量与多样性仍未知，是模型实验前的生死 Gate。
- 近期相邻 benchmark 仍可能覆盖本研究的合取单位；数据构造前必须复核全文，而不是依赖标题。
- 如果机械 oracle 不能独立实现、策略分离无法证明或自然语言映射无法可靠审计，停止执行层。
- 如果浅层基线或 parser/planner 近饱和，收缩论文 claim 或换题，不以复杂训练掩盖问题。
