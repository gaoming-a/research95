# 未来研究候选无模型 Gate v0.1

日期：2026-07-19

## 1. 目的与边界

本文把两个尚未锁定的通信工程大模型候选方向压缩成可证伪的无模型可行性协议。它只
规定科学问题、机械标签、数据谱系、分组划分、简单基线和停止条件，不授权枚举、下载或
读取研究样本，不授权 NIKA/ns-3 环境、容器、模型/API、训练、评估或论文效果 claim。

两个候选均未立项：

1. 候选 A：工具契约下网络故障可辨识性驱动的诊断提交评测；
2. 候选 B：面向 ns-3 仿真代码生成的参数化隐藏关系语义验证。

所有数值门槛都是待作者冻结的 feasibility 建议下限，不是领域公认标准，也不是统计
功效证明。正式样本量只能在未来受权的 feasibility cohort 后按独立组数量、组内相关性
和实践最小效应另行计算。

## 2. 条件选择规则

| 导师/学院边界 | 优先路线 | 当前动作 |
| --- | --- | --- |
| 不强制训练，接受评测协议与数据构建为主要贡献 | A 优先 | 先过完整候选集、只读工具、标签稳定、泄漏和规则平凡性 Gate |
| 明确强制训练，且明确接受 ns-3 代码生成作为通信工程场景 | B 优先 | 先过参数化契约、关系 oracle、闭包划分和普通隐藏测试增量 Gate |
| 强制训练，但不接受 ns-3 场景 | A/B 均不锁定 | 重新审计新的通信场景，禁止给 A 强行添加 LoRA |
| 只接受算法/模型方法创新，不接受 benchmark/protocol 贡献 | A/B 均未达立项条件 | 重新定题 |

作者已确认 EI 小论文不强制模型训练，硬要求是能够发表。因此训练形式本身不再是选题
条件，候选 A 暂列第一顺位；但最终排序仍取决于作者是否接受以评测协议、机械标签和
数据构建为主要贡献，而不要求新的模型结构或训练算法。

## 3. 共同授权链

任何候选都必须依次通过：

1. **D0 学科 Gate**：导师确认应用场景与论文贡献类型；
2. **D1 创新 Gate**：冻结 2024--2026 直接近邻、允许与禁止 claim；
3. **D2 元数据 Gate**：只核对官方来源、许可、版本、计数、依赖和发布边界；
4. **D3 acquisition-only Gate**：作者签核精确仓库、commit、允许路径、文件/字节上限、
   隔离 staging 和旧内容碰撞检查；
5. **D4 scientific-use Gate**：以 staging 中既存文件生成非空、hash-bound future manifest，
   由作者二次签核；
6. **D5 无模型 feasibility Gate**：才允许读取已授权内容、校准机械标签和运行最小环境；
7. **D6 模型行为 Gate**：只有 D5 通过后才允许证明是否存在大模型特有失败；
8. **D7 训练必要性 Gate**：只有简单基线未解决且错误跨组稳定时才允许训练。

当前停在 D2；`future_research_input_manifest_v0_1.json` 为空且未授权。

## 4. 候选 A：网络故障诊断提交边界

### 4.1 允许的科学问题

> 在冻结候选故障空间、诊断答案粒度、只读工具契约、观测归一化和受控环境版本后，
> 一段有序诊断历史是否已经足以唯一确定可提交的诊断答案？

结论必须限定为“闭世界、工具契约相对、经验观测分布下的答案可辨识性”。不得声称
识别了唯一真实故障、证明了绝对证据充分性，或泛化到未知故障和生产网络。

直接边界包括 [NIKA](https://github.com/sands-lab/nika)、
[SADE](https://arxiv.org/abs/2605.04530)、
[AgentAbstain](https://agentabstain.github.io/) 和
[Agentic Abstention](https://arxiv.org/abs/2606.28733)。创新只能是把经典故障可辨识性
实例化成状态级、匹配、可回放的网络诊断提交评测；“分阶段诊断、继续取证、拒答、信息
增益或 LoRA”均不能单独作为创新。

### 4.2 冻结对象与标签

对每个场景冻结：

- 完整适用故障假设集合 `Omega`，包含故障族、目标实体、位置、参数、拓扑和负载；
- 故障到工程可接受诊断答案的映射 `q(h)`；
- 原子只读工具集合、类型化参数、成本、超时、输出 schema 和归一化器；
- 环境重置、随机种子、流量和时间窗；
- 故障—工具—观测的三值兼容规则：兼容、不兼容、未知。

历史必须是有序序列：

```text
H_t = (initial_symptom, (action_1, observation_1, status_1), ...,
       (action_t, observation_t, status_t))
```

定义：

```text
C_plus(H)  = 所有没有被任何已校准观测机械排除的故障假设
C_minus(H) = 所有被每项观测确认兼容的故障假设
Y_plus(H)  = {q(h): h in C_plus(H)}
Y_minus(H) = {q(h): h in C_minus(H)}
```

标签规则：

- `commit`：`|Y_plus(H)| = 1`；
- `continue`：`|Y_minus(H)| >= 2`，且仍存在契约内可推进的只读动作；
- `invalid`：候选为空、真故障被排除、答案映射未定义、兼容性仍未决、环境漂移、越权
  工具、未校准输出，或契约下无法继续辨识。

核心不变量：**提交依据是答案集合唯一，不是故障集合唯一。** 多个故障假设若映射到同一
可操作答案，即使 `|C(H)|>1` 也可提交；只要还对应两个答案就不得提交。

声明内工具失败或超时统一为 `bottom`，必须对所有候选保持兼容，因此：

```text
C(H + bottom) = C(H)
```

工具失败不得排除候选、产生信息增益或把 `continue` 变成 `commit`。解析失败或契约外
新输出进入 `invalid`，不得查看结果后放宽容差。

### 4.3 只读工具契约

NIKA 当前 README 列出 `cat_file`、`exec_shell`、`exec_shell_dual`、服务操作和配置读取等
宽权限工具，因此官方默认工具集不能直接作为本研究工具契约。未来协议必须：

- 只允许枚举的原子诊断工具和白名单参数；
- 禁止任意 shell、复合命令、管道、重定向和任意路径读取；
- 禁止写配置、重启服务、改变接口、注入流量或修复故障；
- 禁止读取注入脚本、问题列表、真值文件、备份配置和答案映射；
- 每个原子动作单独计费，失败模式事前冻结；
- 运行时以调用前后状态哈希和访问审计验证零写入、零真值访问。

### 4.4 随机输出与匹配状态

归一化器必须事前处理时间戳、PID、排序、分辨率、区间、重复日志和失败状态。声称确定性
的工具至少三次独立重置后签名完全一致；随机工具必须在 development-only 回放上冻结
预测集合或工程容差，测试输出不能参与修订。

从同一真实故障与基础歧义历史 `B` 构造：

- `H_plus`：加入真实可执行观测后 `|Y|=1`；
- `H_minus`：候选严格减少但仍有至少两个答案；
- `H_zero`：加入中性、重复或声明内失败观测后候选不变；
- removal control：从 `H_plus` 移除关键观测回到不足状态。

三者必须匹配前缀、调用数、权限、成本、输出 schema 和长度区间。不能通过删除故障名、
答案字段或人工挑两个候选制造歧义；所有合格故障与动作必须由完整适用空间机械枚举。

### 4.5 分组、泄漏与简单基线

组键至少包含：拓扑/场景生成器、负载/目标模板、故障注入机制、目标角色类和工具契约
版本。同一基础故障的所有种子、三元组、参数变体、语言改写和派生序列化必须进入同一
split；至少保留两个完整未见测试组。

直接泄漏零容忍：故障名、注入器、真值、备份文件、问题列表、场景—答案映射、内部
错误码和标签器候选数均不得模型可见。元数据-only、打乱正文、只看最后调用、工具名、
长度和失败码等快捷基线在分组测试上的 balanced accuracy 95% 区间上界若超过 0.60，
必须重构数据。

无模型基线至少包括：always-commit/continue、最佳固定单工具、历史签名查表、浅层规则/
决策树、完整候选兼容求解器、平均信息增益和最坏情况分区策略。完整候选求解器是标签
oracle；若模型推理时也获得相同故障表和兼容表，大模型任务已被符号规则精确解决。

### 4.6 A 的 feasibility Gate

建议结构下限：

- 至少 4 个自然歧义组、4 类故障机制、3 类拓扑/独立场景；
- 至少 100 个基础歧义历史、300 个充分/不足/中性状态；
- 至少 2 个完整未见测试组；
- 标签跨回放一致率不低于 95%，发布状态中真故障保留率为 100%；
- 直接泄漏、写入、越权读取和工具失败缩小候选均为 0。

任一条件触发即对“大模型创新” No-Go：

- 一个固定工具一步解决不少于 80% 的歧义状态；
- 签名查表或浅层规则在分组留出上达到约 0.90；
- 几乎所有状态天然唯一，或契约内几乎永远不可解决；
- 完整候选空间不支持歧义，只能人工配对；
- 中性、失败或 removal control 无法成立；
- 只有随机实例划分有效。

### 4.7 A 的论文递进

EI 小论文只做：机械答案可辨识性标签、匹配状态、过早提交实证、选择性风险和至多一步
安全取证。训练不是前提。

硕士论文只有小论文 Gate 通过后才扩展：多步成本约束、工具失败/随机输出、开放故障集
或第二个独立网络环境。只增加模型、样本或场景不构成毕业论文新问题。

## 5. 候选 B：ns-3 参数化隐藏关系验证

### 5.1 允许的科学问题

> 同一份生成的 ns-3 程序通过编译和名义参数可见测试后，是否仍会在 prompt 已声明的
> 合法参数范围内违反拓扑、协议、流量和统计行为关系？关系测试在相同执行预算下能否
> 发现普通随机隐藏测试遗漏的网络语义错误？

[SIMCODE](https://arxiv.org/abs/2507.11014) 已覆盖自然语言到 ns-3 代码、执行测试与微调；
[GenOnet](https://arxiv.org/abs/2408.13781) 与
[Toward Generative 6G Simulation](https://arxiv.org/abs/2503.13402) 已覆盖生成、测试设计、
调试、执行和反馈。因此“更多测试、执行反馈、变形测试或 LoRA”均不是创新。仅允许主张
具有网络关系约束、随机仿真统计 oracle 和派生闭包隔离的领域评测增量。

### 5.2 主协议：同一代码的参数化隐藏验证

基础任务定义为：

```text
t = (specification, declared_parameter_contract, frozen_environment,
     reference_program, observers, visible_tests, hidden_relation_tests)
```

模型只生成一次程序 `p`。所有可变参数、类型和合法范围必须在 prompt 中声明；隐藏的只能
是具体取值、组合、种子、参考输出和判定脚本。若 prompt 只要求固定10个节点，而隐藏测试
要求100个节点，属于增加需求，不是公平反事实验证。

主要失败标签：

```text
visible_pass_hidden_fail(p,t) = visible_tests(p) 全通过
                                且至少违反一项隐藏网络关系
```

build error、crash、timeout、NaN 和观测缺失均失败。结构语义按节点/链路、拓扑同构、
协议栈、流端点和可达性精确判定；吞吐、时延和丢包等随机行为必须与参考程序做配对差或
分布等价比较。

双 prompt 协议，即分别对 base/transformed prompt 生成两份代码，再检查跨程序关系，
混合了 prompt 敏感性、解码随机性和网络语义错误，并与通用 metamorphic prompt testing
高度重合；它不进入 EI 小论文主轴，只可作为毕业论文次级扩展。

### 5.3 关系 oracle

每项关系必须声明适用前提、结构/行为观测、正向关系、应变化的负控制、工程容差和种子
计划。第一层优先关系：

- 物理单位等价；
- 节点、地址和流标识重命名后的拓扑同构；
- 显式分配随机流后的对象创建顺序置换；
- 应用起止与仿真终止时刻同步平移后的相对时间不变；
- 完全隔离组件的复制或添加不影响原组件标准化行为。

传播时延、瓶颈速率、负载、链路失效、路由、移动性和干扰通常没有普适单调规律，只能
在受限前提下由参考程序差分给出 oracle，不能凭直觉写标签。

随机性必须冻结 ns-3 与模块 commit、编译器和构建参数；固定 `RngSeed`、枚举 `RngRun`，
对可识别组件显式分配随机流。流对齐时使用配对差，无法证明对齐时比较独立分布。容差
必须来自通信工程意义，种子数由功效设计确定；参考程序自身关系不稳定则删除任务，不能
放宽容差。

### 5.4 闭包分组、泄漏和基线

先建立任务溯源图，再按连通分量划分。以下对象必须连边并整体进入同一 split：同一原始
任务、参考程序/AST近克隆、同一 ns-3 example 或课程模板、数值/名称改写、全部关系变体、
mutant、修复和反馈轨迹。派生一万个参数组合仍只算一个独立基础任务。

泄漏审计包括：prompt/程序/测试哈希、AST近重复、隐藏参数和关系名的文件名/注释/错误
消息泄漏、测试参考进入训练或RAG、代码长度/测试数/难度/协议模板捷径，以及候选程序
读取测试配置。SIMCODE 已公开，必须披露预训练污染风险，并以新参数化规格和闭包留出
降低影响。

同预算强基线至少包括：SIMCODE可见测试、普通随机参数隐藏测试、候选—参考直接差分、
mutation testing、AST/静态规则、官方文档检索、编译/运行/可见单测反馈、现有测试设计—
执行循环，以及由类型化规格直接生成模板代码的非LLM编译器。

### 5.5 B 的 feasibility Gate

来源元数据当前存在明确风险：SIMCODE论文称400题，仓库表格为111+101+189=401；仓库
无正式 release，许可为 [CC BY-NC 4.0](https://github.com/tasnim7ahmed/simcode-bench/blob/main/LICENSE.md)。
未来必须冻结完整commit、核清计数、第三方来源和衍生发布边界。

建议结构下限：

- 闭包后至少 120 个独立基础任务，锁定测试不少于 60 个；
- 至少 4 个网络任务族和 4 个关系族；
- 至少 80% 入选任务可形成公平参数契约和不修改候选逻辑的观测器；
- 参考程序三次干净构建的结构结果完全一致；
- 随机关系标签重放一致率不低于 95%；
- 独立正确实现误拒率的 95% 上界低于 10%；
- 等执行预算下，关系套件相对普通隐藏测试的额外检出率至少 10 个百分点且组级区间
  下界大于0；
- 非执行词法/AST快捷基线 AUROC 低于0.85，达到0.90即 No-Go。

任一条件触发即 No-Go：

- 固定任务无法公平参数化或闭包后独立任务不足；
- 关系依赖人工或 LLM judge 逐样本判定；
- 参考关系随种子或环境不稳定；
- 普通随机隐藏测试检出关系套件90%以上的错误；
- 模板生成器、AST规则或直接规格编译近乎解决任务；
- 贡献只能表述为“给SIMCODE增加更多测试或LoRA”。

### 5.6 B 的论文递进

EI 小论文只研究参数化同代码隐藏关系评测、可见测试盲点、闭包划分和等预算普通隐藏
测试比较。只有训练必要性 Gate 通过时，7B/8B LoRA 才可作为次要方法。

硕士论文从“检测”扩展到一个新问题：关系约束下的可验证程序修复与跨协议/版本泛化。
主动测试、双 prompt、版本迁移、欠规格澄清不得同时堆入主线。

## 6. 共同训练必要性 Gate

未来即使无模型 Gate 通过，也只有同时满足以下条件才允许训练：

- 至少两个基础模型家族在完整分组留出上出现同类稳定失败；
- A 的不足状态错误提交率，或 B 的 `visible-pass-hidden-fail` 比例，建议至少20%；
- 错误横跨至少3个独立故障/网络任务族；
- 规则、查表、模板、AST、检索、普通SFT和普通执行反馈仍留下明确缺口；
- 相对等数据、等token或等执行预算的最强基线，分组增益建议至少5个百分点且置信区间
  排除0；
- 改进不能通过降低提交覆盖率、增加重试或牺牲完整证据RCA/可见测试通过率获得。

否则保留为评测协议论文或直接停止，不得为了使用GPU微调。

## 7. 当前停止点与下一项作者决策

当前没有任何候选通过运行时标签、简单基线或训练必要性 Gate，也没有最终题目。模型
